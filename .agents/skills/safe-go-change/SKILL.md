# Safe Go backend change

Используй этот skill для исправлений, новых HTTP-сценариев, изменений Domain/Application/Adapters, конфигурации и работы с PostgreSQL.

## До редактирования

1. Прочитай `AGENTS.md`, `backend/AGENTS.md` и применимые файлы `rules/`.
2. Выполни `git status --short`; зафиксируй существующие изменения и не перезаписывай их.
3. Изучи весь путь данных для задачи: router → handler/DTO → service → port → adapter → domain errors, а также обратный путь ответа.
4. Найди существующие тесты и baseline. Не предполагай, что README полностью актуален.
5. Для многофайловых изменений используй OpenSpec `explore` и `propose`; для малой локальной правки достаточно короткого плана.

## Во время реализации

- Меняй минимальный набор файлов.
- Соблюдай Ports & Adapters и направление зависимостей.
- Не переносить бизнес-правила в Gin handlers и SQL — в services/domain.
- Не добавляй зависимости без реальной необходимости.
- Не меняй API, схему БД, CSV формат или поведение ошибок без требования.
- Синтетические CSV проекта допустимы. Соблюдай rules/data-safety.md; не читай .env, credentials и секреты без необходимости.
- Не делай commit/push и не запускай разрушающие команды.

## После реализации

1. `gofmt` для изменённых Go-файлов.
2. Точечные тесты затронутых пакетов.
3. Из `backend/`: `go test ./...`, `go vet ./...`, `go build ./...`.
4. Из корня: `git diff --check`.
5. Для DB/Docker изменения — интеграционная проверка только если окружение доступно; не удаляй volumes.
6. Проверь `git diff` и перечисли все изменённые файлы.

В отчёте честно отличай запуск теста от предположения о его прохождении.
