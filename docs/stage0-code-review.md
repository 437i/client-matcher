## Findings

Critical, High и Medium не найдено.

**Low-1. Нет реального случая «нет потенциальной пары».**
- Файл: `repo_dataset_test.go:124`.
- Сценарий: roadmap §8 требует сохранить «отсутствие потенциальной пары». «Азамат Далгатов» (site 1326) в `crm.csv` не встречается: паттерн «Далгатов» в grep по CRM ничего не вернул.
- Сейчас в качестве no-match проверяется только `"я"`. Это случай короткого запроса, а не отсутствия пары.
- Влияние: регрессия, при которой запись без пары начнёт получать ложных кандидатов (например, через fuzzy), не будет поймана.
- Исправление: добавить `{"Азамат Далгатов", []string{}}` и такой же запрос для других site-записей без пары. Это гипотеза: результат нужно проверить запуском, я его не гонял.

**Low-2. Ожидаемые ID заданы только для 14 из 55 site-записей.**
- Файл: `repo_dataset_test.go:78-83,100`.
- Остальные 41 записи проверяются только на стабильность и лимит. «Все site-запросы стабильны» из `PROJECT_STATUS.md:19` верно, но предсказуемость результата для 41 записи не зафиксирована.
- Влияние: неочевидная деградация на «обычных» парах (например, 276 «Соня Кузнецова» → 6056) не будет поймана.
- Исправление: либо расширить `known`, либо явно указать в статусе, что ожидания заданы выборочно. Вывод roadmap «тесты фиксируют ожидаемые результаты» остаётся достаточным.

**Low-3. Проверка даты слабая, комментарий вводит в заблуждение.**
- Файл: `repo_dataset_test.go:143-154`.
- Тест проверяет только `s.Birthday != c.Birthday`. Конкретные даты 2020-11-15 и 2020-12-15 не зафиксированы.
- Комментарий говорит, что расхождение «не удаляет кандидата», но этот тест наличие кандидата не проверяет. Оно проверено в таблице на `:112`.
- Исправление: сравнивать с литералами дат и поправить комментарий. Это косметика.

**Low-4. Пустой список ожидаемых ID слабо защищён от опечатки в `want`.**

- `tc.want[:min(1,len(tc.want))]` безопасен. Но для `"я"` проверка лимита ничего не проверяет, потому что обе стороны пустые. Это не дефект.

## Гипотезы (не дефекты, требуют проверки)

- **H-1.** `agent-workflow.md:35` отключает hooks через `disableAllHooks:true`. Если защита чтения секретов у Claude реализована hook'ами, а не `permissions.deny`, для headless-запуска она снимается, и запрет «не читать .env» держится только на тексте задания. Я не открывал `.claude/settings*`. Стоит убедиться, что секреты закрыты через `deny`-правила.
- **H-2.** `agent-workflow.md:41` сохраняет Auto Memory при запуске с Read/Grep/Glob. Нужно убедиться, что при запрете Write память не пишется и не читается лишнего. Я этого не проверял.
- **H-3.** В `repo_dataset_test.go:19` `len(repo.byID) == 200` совпадает с числом строк файла, значит пропущенных невалидных строк нет. Но тест не проверяет «пропусков нет» отдельно: две компенсирующие ошибки (пропуск и дубль) считаются невозможными, потому что дубль ID даёт ошибку загрузки.
