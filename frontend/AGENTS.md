# Frontend — локальные правила агентов

## Область

Здесь находится одностраничное приложение client-matcher: React + TypeScript + Vite. Это слой представления над существующим Go/Gin API, а не второй backend: бизнес-правил сопоставления здесь нет и быть не должно.

## Перед изменениями

1. Прочитай корневой `AGENTS.md`, `rules/frontend.md` и `rules/non-technical-ux.md`.
2. Посмотри `package.json`, `vite.config.ts`, `src/`, тесты, `Dockerfile` и `nginx.conf`.
3. Прочитай `../backend/openapi/swagger.yaml` и сгенерированные типы `src/api/schema.d.ts`, прежде чем менять интеграцию с API.
4. Выполни `git status --short` и сохрани пользовательские изменения.
5. Синтетические CSV проекта допустимы; не читай .env, ключи и секреты.

## Архитектура

- Код UI разбит по feature-папкам: `crm-search`, `site-lookup`, `link-review`, `saved-links`.
- HTTP-вызовы живут только в `src/api`: `client.ts` (клиент и хуки TanStack Query) и `errors.ts` (коды ошибок → русские тексты).
- Типы API генерируются из `../backend/openapi/swagger.yaml` командой `npm run api:types`. Свои DTO не заводи: сгенерированные типы — единственный источник.
- Backend отвечает за сопоставление фамилии и даты рождения. Не проверяй это в браузере.
- Серверное состояние — TanStack Query; транзиентное состояние сценария — `src/lib/workflow.ts`.
- Правило актуальности пары: запись сайта помнит, для какого клиента и номера она найдена. Смена клиента или номера делает её недействительной, и проверка повторяется в обработчике сохранения.
- Переиспользуй примитивы shadcn/ui и единую тему из `src/index.css`.

## UX

Пользователи — сотрудники фонда с небольшим опытом работы с компьютером. Требования `rules/non-technical-ux.md` обязательны: понятный русский язык, один основной сценарий, постоянные подписи полей, пояснения рядом с непривычными понятиями, понятные названия источников, явные следующие действия.

Показывай запись основной базы и запись сайта до сохранения; пара и оба номера должны быть видны без догадок. Никогда не выбирай клиента и не сохраняй связь автоматически. При ошибке сохраняй введённые данные, объясняй причину и один безопасный следующий шаг, не допускай повторной отправки и показывай постоянное подтверждение успеха.

Спокойный, не перегруженный визуальный стиль, читаемый текст, крупные элементы управления, поддержка клавиатуры, видимый фокус, узкие экраны. Не используй технический жаргон, кнопки без подписей, декоративные метрики и панели.

## Команды

Требуется Node.js `^22.22.2 || ^24.15.0 || >=26.0.0` — минимум задаёт `jsdom@31`.

```bash
npm run dev        # dev-сервер с прокси /api → http://localhost:8080
npm run typecheck  # tsc -b: приложение, тесты и конфигурация сборки
npm run lint       # eslint
npm run test       # vitest run
npm run build      # сборка в dist/
npm run api:types  # перегенерация типов из backend/openapi/swagger.yaml
```

Не утверждай, что проверка прошла, пока она не запущена. Не меняй backend, исходные пользовательские данные и тома Docker. Не коммить и не отправляй изменения без прямой просьбы.

## Отчёт о проверке

Ниже — эвристический проход по сценарию новичка из `rules/non-technical-ux.md`, выполненный на синтетических ответах (тесты и мок-ответы). Это оценка по правилам, а не тестирование с реальными сотрудниками фонда.

| Вопрос | Итог |
| --- | --- |
| Понятно ли, с чего начать | Да: первый экран — заголовок «Связать клиента с записью на сайте», подзаголовок и шаг «Шаг 1. Найдите человека в основной базе (CRM)» с полем и кнопкой «Найти клиента» |
| Понятно ли, что вводить и откуда взять номер записи | Да: постоянные подписи; подсказка у номера объясняет, что это номер, полученный при добавлении клиента на сайт |
| Различимы ли похожие кандидаты | Да: полное имя крупно, рядом дата рождения, организация и номер в основной базе |
| Понятно ли, что свяжется | Да: блок «Проверьте данные» с колонками «Основная база (CRM)» и «База сайта», оба номера подписаны |
| Объясняет ли ошибка, что делать дальше | Да: каждому коду backend соответствует свой текст с одним следующим шагом, введённые данные не теряются, а поиск можно повторить без изменения введённого текста |
| Заметно ли подтверждение и находится ли связь | Да: постоянный блок «Готово» с обоими номерами, список сохранённых связей обновляется |
| Можно ли скачать CSV без понимания файлов | Да: кнопка «Скачать CSV» с пояснением, что в файле пары номеров |
| Выполняется ли задача без мыши | Да: сценарий с клавиатуры закреплён тестом, фокус после выбора клиента и после «Изменить выбор» переводится предсказуемо |

Что осталось непроверенным в этой среде: измерение контраста (в jsdom нет canvas, поэтому axe помечает правило как непроверяемое — палитра проверена расчётом), реальный браузерный прогон на ширине 320 px и при увеличении 200 %, работа со screen reader, а также проверка на сотрудниках фонда.
