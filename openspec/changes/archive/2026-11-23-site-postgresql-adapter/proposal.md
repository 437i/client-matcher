## Why

После завершения Stage 1 приложению нужен второй источник записей сайта. PostgreSQL-адаптер позволит читать записи по подтверждённому идентификатору каталога и поддержит существующую демонстрацию через CSV.

## What Changes

- Добавить чтение `public.children` по первичному ключу через отдельный PostgreSQL pool и явный выбор источника сайта. CSV остаётся режимом по умолчанию.
- Привести Site ID в Go к `int64` и перевести `client_links.site_id` в `BIGINT` новой транзакционной миграцией. HTTP и CSV export сохраняют строковое десятичное представление.
- **BREAKING** для прежних произвольных строковых Site ID и внутренних Go-интерфейсов. Несовместимые сохранённые значения блокируют миграцию. Для ранее выданных assessment token потребуется повторная оценка после обновления.
- Преобразовывать `birthday` из UTC в календарную дату Москвы. Поддержать NULL и отдельно обработать некорректные даты.
- Границы этапа определены roadmap. SSH относится к Stage 3, поисковый HTTP API к Stage 4, frontend к Stage 5, Bitrix24 к Stage 6. Проверки выполняются в временных синтетических БД.

## Capabilities

### New Capabilities

- `site-record-source` обеспечивает чтение записей сайта через PostgreSQL и совместимую демонстрацию через CSV.

### Modified Capabilities

- `link-confirmation` уточняет допустимый Site ID на HTTP-границе и сохраняет уникальность при переходе на числовой ключ.
- `matching-assessment` закрепляет каноническую идентичность Site ID в токене и повторную оценку после смены формата.

## Impact

Затронуты модели SiteClient, ClientLink и Decision, порты, сервисы, CSV и PostgreSQL адаптеры, HMAC-токен, HTTP handlers и DTO, OpenAPI, серверная конфигурация и новая Goose-миграция собственной БД. Контракт CRM ID остаётся строковым.
