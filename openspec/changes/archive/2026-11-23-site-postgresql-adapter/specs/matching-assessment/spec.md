## MODIFIED Requirements

### Requirement: Assessment связан с актуальными источниками
Система SHALL выдавать проверяемый короткоживущий assessment token, связанный с обоими ID, значениями полей оценки и версией правил. Изменение любой из этих частей SHALL делать подтверждение устаревшим.

#### Scenario: Изменение данных
- **WHEN** после оценки изменилось ФИО, дата или версия правил
- **THEN** сохранение с прежним токеном возвращает assessment_stale и требует повторной оценки

#### Scenario: Подмена токена
- **WHEN** токен повреждён, истёк или относится к другим ID
- **THEN** backend отклоняет его без создания связи

#### Scenario: Каноническая идентичность сайта
- **WHEN** запросы используют допустимые варианты записи одного Site ID
- **THEN** токен связан с одним числовым ключом. Другой ключ отклоняется.

#### Scenario: Прежняя версия токена
- **WHEN** после обновления передан токен прежнего формата
- **THEN** backend возвращает invalid_assessment_token и требует новой оценки
