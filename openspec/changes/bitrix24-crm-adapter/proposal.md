# Proposal

## Why

Stage 4 подключает смарт-процесс «Дети» в Bitrix24 как CRM-источник production. Локальная разработка и тесты продолжают использовать синтетический CSV.

## What Changes

- Выбор `CRM_SOURCE=csv|bitrix24` при запуске. Локальный default — `csv`, production Compose явно выбирает `bitrix24`. Сбой выбранного источника возвращается как ошибка.
- Outbound adapter реализует существующий `CRMReader` поверх классического REST через официальный B24GoSDK `v0.2.0`. SDK обслуживает webhook, REST envelope, страницы и повторы.
- Поиск фильтрует карточки на сервере, ранжирует кандидатов по Stage 0 и ограничивает объём и длительность чтения. Исчерпание бюджета при наличии продолжения возвращает техническую ошибку.
- Адаптер сохраняет исходный `title`, отдельные компоненты имени и календарную дату. В оценке пары `title` определяет допустимые доказательства имени. Существующее повторное чтение связывает оценку с актуальной карточкой.
- Использование настоящего webhook, реальные данные и production smoke test отложены. Stage 5 Search HTTP API, Stage 6 frontend, Stage 7 подготовка к эксплуатации, клиника, CRM-индекс, полная синхронизация, авторизация приложения и изменения OD или миграций находятся за рамками change.

## Capabilities

### New Capabilities

- `crm-record-source` определяет режимы источника, свежую карточку, авторитетное имя, ограниченный поиск и безопасные ошибки.

### Modified Capabilities

- `matching-assessment` дополняется правилами использования авторитетного `title`, известных ролей имени и актуальности fingerprint.

## Impact

Затронуты Go-зависимости, CRM outbound adapter, доменная модель и оценка имени, снимок assessment, конфигурация и composition root, Compose, тесты и документация. Порт `CRMReader`, строки ID, Gin routes, HTTP DTO, OpenAPI и уникальность связей в OD сохраняются. Scope проверки включает синтетические wire tests и CSV baseline Stage 0. Демонстрационные связи не переносятся.
