## MODIFIED Requirements

### Requirement: Контракт и безопасные ошибки
Assessment и создание SHALL документироваться в backend OpenAPI; поиск, CSV export, идентификаторы string и существующие поля успешного ответа связи SHALL сохраняться. Ошибки SHALL NOT раскрывать SQL, токены или исходные персональные поля.

#### Scenario: Описание нового сценария
- **WHEN** потребитель читает OpenAPI
- **THEN** POST /api/v1/link-assessments и расширенный POST /api/v1/links описывают nullable birthday, статусы, причины, токен и ошибки, соответствующие фактическим DTO

#### Scenario: Десятичный Site ID
- **WHEN** клиент передаёт Site ID как строку десятичного целого в диапазоне int64 в path, assessment или create
- **THEN** сравнение выполняется по числовому значению, а карточка сайта, ответы связей и CSV export используют каноничную десятичную строку

#### Scenario: Недопустимый Site ID
- **WHEN** непустой строковый Site ID содержит дробь, экспоненту, недесятичные символы или выходит за диапазон int64
- **THEN** возвращается 400 invalid_id до вызова источников. JSON-число отклоняется на этапе binding.
