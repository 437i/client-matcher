# Proposal

## Why

Stage 2 уже подключает PostgreSQL сайта напрямую. Для production обе удалённые базы доступны приложению через разные SSH-серверы, а локальному стеку по-прежнему нужны CSV и прямая PostgreSQL для связей.

## What Changes

- Добавить production-подключения SITE и OD с независимыми SSH-сессиями. SITE использует пароль SSH, OD — закрытый ключ из файла. Оба подключения проверяют доверенные ключи серверов через `SSH_KNOWN_HOSTS_PATH` и отдельно аутентифицируются в PostgreSQL.
- Восстанавливать каждую SSH-сессию с ограниченным exponential backoff и обновлять соединения соответствующего пула PostgreSQL. Дождаться готовности обеих БД и завершения Goose через OD перед запуском HTTP. При остановке освободить HTTP и ресурсы подключений.
- Применять существующие миграции и выполнять запросы хранилища OD в схеме `apps`. Таблица версий Goose также располагается в `apps`.
- Добавить отдельный production Compose с сервисами `backend` и `frontend`. Локальный Compose сохраняет свою БД, мигратор и CSV по умолчанию. CRM продолжает читать `CRM_PATH` в обоих режимах.
- За пределами Stage 3 остаются Bitrix24, CRM API, `WEBHOOK_URL`, бизнес-правила поиска, оценки и сохранения, прикладная авторизация, администрирование внешних БД, дополнительная инфраструктура деплоя и ретроспективное согласование предыдущих этапов.

## Capabilities

### New Capabilities

- `ssh-postgres-connectivity` — проверяемые и восстанавливаемые production-подключения к SITE и OD, изоляция схемы OD, миграции и порядок запуска backend.

### Modified Capabilities

- `site-record-source` — выбор транспорта отдельно от выбора источника сайта, включая обязательный PostgreSQL через SSH в production.
- `frontend-delivery` — отдельный production Compose использует существующую доставку frontend и same-origin API, сохраняя локальный сценарий.

## Impact

Изменения при Apply затронут `backend/internal/platform`, `backend/cmd/server`, зависимости Go, упаковку миграций в backend image, отдельный Compose и документацию Stage 3. Существующие адаптеры получают прежние типы пулов, HTTP-контракт и SQL миграций сохраняются. SITE PostgreSQL 10.23 обслуживает запросы только на чтение `public.children`. OD PostgreSQL 16.15 обслуживает схему связей и её миграции под `OD_USER`.

PostgreSQL 10.23 — фиксированная версия внешней SITE и находится за пределами официальной матрицы pgx v5.12.0 (PostgreSQL 14+). Готовность Stage 3 требует успешного подключения через SSH и чтения `id`, `title` и `birthday`, включая NULL в `birthday`, на синтетической PostgreSQL ровно 10.23. Результат подтверждает этот сценарий. Провал блокирует завершение Stage 3 и выносится на отдельное решение.
